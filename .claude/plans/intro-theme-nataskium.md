# План: фирменная интро-тема Nataskium (перенос из прототипа HyperFrames)

## Цель
Перенести утверждённое фирменное интро Nataskium (плата, робот-«а», сборка слова, сигнал по дорожке, вылет первого вопроса) из прототипа `hyperframes-lab/work/brand-intro` в `apps/web` как **тему кодом** (Vue + GSAP) по ADR 0015, с выбором темы учеником на стартовом экране, не нарушая ADR 0014.

## Что изучено
- `CLAUDE.md`, `docs/adr/0014-play-inside-intro-player.md`, `docs/adr/0015-intro-themes.md` (статус **«Предложено»**), `docs/architecture.md` (CSP через hash в Caddy, `script-src 'self'` без `'unsafe-inline'`).
- `widgets/intro-player/IntroPlayer.vue`: фазы `start → playing → done`; слот с игрой монтируется **только** в `done` (`v-if`), значит таймер задания стартует при монтировании игры (`store.start` в `onMounted` ставит `startedAt`). Проп `theme?: 'night' | 'light'` уже есть (тон), снаружи его никто не передаёт. Статичный слой `.intro-player__pcb` (`pcb-white.webp`, свои маски). Наборы `--g-*` для тёмного и светлого тона.
- `pages/PlayPage.vue`: `IntroPlayer :key="view.kind"`, интро только у загруженного задания. `/play/**` уже `ssr: false`.
- `pages/IntroPreviewPage.vue`: dev-only (`DEV_ONLY_PATHS`), `?src=` с белым списком пути.
- `widgets/quiz-play/components/PlayQuestion.vue`: фокус на `h1` в `onMounted` через `focusInPlace` (`scrollIntoView`).
- `widgets/true-false-play`: фокус на `StatementCard` (`defineExpose({ focus })`).
- `widgets/matching-play/components/MatchingBoard.vue`: летящая плитка `.matching-board__lifted { position: fixed }`, `TermChip` двигается `transform` на самой плитке.
- `shared/ui/AppLogo.vue`: пути букв; «N», «t» и голова в **одном** `path`, в прототипе они разделены.
- `assets/styles/mixins.scss`: `$board-pattern` (`nataskium-pcb-pattern.svg`), `$board-tile-size`, `board-zones`.
- `global.scss`: каскад `--z-*` (до `--z-drag-chip`).
- Локали `ru/en/de/fr`, тест паритета ключей `shared/i18n/locales.test.ts` (ключи и плейсхолдеры должны совпадать во всех 4 файлах).
- Прототип: `index.html` (9,4 с, вопрос-демо с 7,1 с), `compositions/brand.html` (таймлайн), `compositions/question-demo.html` (рамка от точки входа в обе стороны, точки, полосы-заглушки, `scale` к полной ширине), `assets/layout.js` (раскладка от размера кадра, ландшафт и телефон), `assets/palette.css` (`--i-*` для `dark` и `light`), `brand-intro-phone/index.html` (1080×2000).
- В `apps/web` **нет прямой зависимости `zod`** и ни одного импорта из `'zod'`: zod приходит транзитивно через `@nataskium/shared` (`zod ^4.6.7`).

## Архитектура (где что лежит по ФСД)

```

├── components/

├── catalog.ts                            каталог тем (код, не загрузка из сети) + проверка схемой
├── types.ts                              ThemeKey, ThemeKind ('code' | 'video'), Tone ('dark' | 'light'), IntroEntrance, IntroSceneApi
├── nataskium/

src/features/intro-theme-select/          действие ученика «выбрать тему»

src/features/play-session/                (существует) + ключ и композабл вылета

├── useFirstEntrance.ts                   инжект контекста; без контекста — сразу «приземлено» (старые тесты не меняются)

```

Направление импортов:
- `pages/PlayPage` → `widgets/intro-player` + `features/intro-theme-select` + `entities/intro-theme`.
- `widgets/intro-player` → `entities/intro-theme` (рисует сцену) и `features/play-session` (ключи).
- `widgets/quiz-play | matching-play | true-false-play` → `features/play-session` (`useFirstEntrance`). Виджет в виджет не импортируется.
- `features/play-session` → `entities/intro-theme` (только тип и фабрики вылетов). Сущность фичи не импортирует.

**Состояние выбора темы — локальный `ref` в `PlayPage`**, без `store.ts`: выбор не переживает навигацию и не запоминается (ADR 0015). `:key="view.kind"` пересоздаёт проигрыватель, выбор живёт в странице и не теряется. Контекст вылета (один раз на запуск) — `provide` из `IntroPlayer`, тоже без Pinia.

**Палитры.** Цвета сцены `--i-*` из `palette.css` переносятся в `<style scoped>` у `NataskiumScene.vue` модификаторами `--dark` и `--light` (hex для статичных, `rgb(r g b / a)` для прозрачных). Цвета игры по-прежнему `--g-*` в `IntroPlayer`: тон темы включает существующий модификатор `intro-player--light`. Новых `--g-*` не нужно, кроме, возможно, `--g-frame` (цвет рамки карточки, `#4573F4` в обоих тонах) — если ответ на вопрос 3 будет «рамка остаётся».

## Шаги

Каждый шаг заканчивается: `npm run lint`, `npm run typecheck`, `npm test` в `apps/web`, ручная проверка на `/intro-preview` (dev-only) и критерий успеха шага. Коммиты делает пользователь сама и только по своей просьбе: в шагах ниже отмечены **точки сохранения** — момент, когда предложить ей коммит перед правкой 3+ файлов или публичного API.

### 0. Подготовка [small, без кода]
- Пользователь принимает ADR 0015 (сейчас «Предложено») и отвечает на открытые вопросы ниже. Без ответов на 1, 2, 3, 5, 6 и 11 шаги 3, 7 и 9 начинать нельзя.
- **Точка сохранения:** рабочее дерево чистое (`git status` чист на старте), коммит не нужен.

### 1. Каталог тем: типы, схема, данные [small]
- Слой `entities/intro-theme`: `types.ts` (`ThemeKey`, `ThemeKind`, `Tone`), `catalog.ts`: массив тем (ключ, вид `code`, тон, ключ i18n названия, компонент сцены через `defineAsyncComponent`), `DEFAULT_THEME_KEY`, `findTheme(key)` (неизвестный ключ — тема по умолчанию).
- Проверка Zod: схема записи (ключ `^[a-z0-9-]+$`, вид и тон из enum; у тем-роликов https-адреса только бакета тем — заранее, но без записей). Для вида `code` компонент проверяется не Zod, а типом. Откуда берётся Zod — вопрос 9.
- `index.ts` экспортирует только публичное: `INTRO_THEMES`, `DEFAULT_THEME_KEY`, `findTheme`, типы.
- **Тесты:** `catalog.test.ts`: каталог проходит схему, ключи уникальны, тема по умолчанию есть в каталоге, `findTheme('unknown')` возвращает её.
- **Критерий:** тесты зелёные, в UI ничего не меняется.

### 2. Локализация названий тем и подписей выбора [small]

- Все 4 файла меняются **в одном шаге**: `locales.test.ts` сверяет ключи и плейсхолдеры.
- **Тесты:** существующий `locales.test.ts` (не правится, просто проходит).
- **Критерий:** паритет ключей зелёный. После правки локалей перезапустить контейнер `web` (HMR локалей не работает).

- **Тесты:** нет. Проверка: `npm run build` собирается, gsap в отдельном чанке (`.output`), главный бандл не вырос.

### 5. Раскладка сцены `nataskium/layout.ts` [small]
- Порт `layout.js` в чистую TS-функцию `introLayout(width, height)` с константами под именами из прототипа (`LOGO_MAX_WIDTH`, `HERO_HEAD_PX`, `ROBOT_EDGE_GAP`…). Сюда же `robotFarOffset` (робот не уезжает за край на узком кадре) и маршрут сигнала до **переданной** точки входа.
- **Карточная часть `layout.js` в приложение не переносится.** Геометрия вылета берётся из реального DOM вопроса: число вариантов, картинки, верхняя полоса, таймер и кнопка у разных заданий разные, а «Начать» к тому же меняет размер контейнера полным экраном.
- Центры букв (в прототипе `getBBox()`) — именованные константы в координатах viewBox `145 170 1880 357`: в happy-dom `getBBox` и `getTotalLength` нет, а в рантайме они не нужны.
- **Тесты:** `layout.test.ts` — 16:9 (1920×1080, ноутбук 1280×720), 4:3 планшета, телефоны (360×640, 390×844, 1080×2000 как в прототипе): лого в кадре с полями, робот на дальней точке не выходит за правый край с `ROBOT_EDGE_GAP`, `heroScale > 0`.
- **Критерий:** значения для 1920×1080 и 1080×2000 совпадают с прототипом (сверить со снимками `.snap/`).

### 6. Сцена `NataskiumScene.vue` [large → делится на 6a и 6b]

> Уточнение 2026-11-20: в прототипе исправлен тайминг — лого уменьшается 2.8–3.3 с, робот трогается вправо в 3.05 с (было оба 2.8–3.55), иначе крупная голова на миг выезжала за край на телефоне. Переносить с этими значениями. Раскладка — `nataskium/layout.ts` (шаг 5), центры букв — `LETTER_CENTERS_VIEW`.

**6a. Статичная сцена (без анимации).** Разметка SVG по прототипу: плата (`$board-pattern`, зоны по углам как у `#brand-pcb`; маска статична, анимируется только `opacity` обёртки), лого из `logoPaths.ts`, слой сигнала. Палитра `--i-*` модификаторами тона. Сцена `aria-hidden="true"`, `pointer-events: none`, `position: absolute; inset: 0` под содержимым, без `transform` на корне сцены. Конечное состояние — «чистая сцена»: фон и плата, без лого. `AppLogo.vue` **не меняется**: пути копируются в `logoPaths.ts` (риск расхождения — в «Рисках»).
- `IntroTheme.vue` рендерит сцену по ключу.
- **Проверка:** `/intro-preview?theme=nataskium-dark|nataskium-light` показывает чистую сцену и (временно, флагом dev-страницы) кадр с собранным лого.
- **Тесты:** `nataskiumScene.nuxt.test.ts`: модификатор тона, `aria-hidden`, нет `v-html`.

**6b. Таймлайн.** `nataskium/timeline.ts` собирает GSAP-таймлайн 1:1 с `brand.html`: плата 0–1,2 с, голова 0,5 с, антенна 1,2 с, глаза 1,5/1,56 с, взгляд 2,0–2,7 с, уменьшение и отъезд 2,8 с, обратный ход `RIDE` 3,55 с + 1,0 с с появлением букв по прохождению робота (вспышка контура → заливка), «N» и точка над «i», моргание, растворение лого 5,8 с. Метка **`clean`** — после растворения (около 6,25 с). Сигнал **в таймлайн интро не входит**: он часть вылета (шаг 9), потому что конечная точка известна только после монтирования вопроса.
- Обводка букв: атрибут `pathLength="1"` и `strokeDasharray/offset` в долях вместо `getTotalLength()`. Проверить в iOS Safari (e2e на WebKit и вручную).
- Только `transform` и `opacity` (и `stroke-dashoffset` у тонких линий). Без `filter`. Тень карточки светлого тона из прототипа (`drop-shadow`) не переносится.
- API компонента через `defineExpose`: `play(): Promise<void>` (резолвится на `clean`), `skip()` (`tl.seek('clean')` + `pause`), `signalTo(point): Promise<void>` (шаг 9). Событие `clean`.
- Всё создаётся внутри `gsap.context(() => …, root)`; `onBeforeUnmount` вызывает `ctx.revert()` (таймлайны убиваются, inline-стили снимаются).
- **Тесты (gsap замокан, проверяется договор, а не движение):** `play` резолвится после `clean`; `skip` ставит сцену в `clean` синхронно; размонтирование вызывает `revert`; при ошибке загрузки чанка gsap компонент сразу отдаёт `clean`.
- **Критерий:** на `/intro-preview?theme=…` анимация совпадает с прототипом на 1920×1080 и 390×844 (сравнить с `.snap/frame-*`); в Performance-панели Chrome при CPU ×4 нет длинных кадров на этапе букв.

### 6c. Звук интро [medium, параллельно шагам 1–5, по ответу на вопрос 12]

Добавлено по просьбе пользователя 2026-11-20.
- Подобрать звук до финальной настройки таймингов в шаге 6b: акценты (робот встал на место, точка над «i», приземление карточки) удобно подгонять в прототипе HyperFrames, он проигрывает звук вместе с анимацией.
- Лицензия: коммерческое использование и содержание для детей; источник записать в документацию темы. Подборку вариантов с проверенными лицензиями готовит Claude, выбирает пользователь.
- Вид звука (вопрос 12): один трек на всё интро или набор коротких звуков к событиям таймлайна (импульс, вспышки букв, приземление). Набор гибче: на телефоне тайминг другой, а звуки запускаются из таймлайна в нужный момент.
- Звук включается по «Начать» (жест пользователя, ADR 0014), уважает кнопку звука проигрывателя; «Пропустить» и reduced motion звук интро не играют.
- Файлы небольшие (десятки КБ), лежат рядом с темой в репозитории; формат с поддержкой iOS Safari (AAC/MP3). Бакет и CSP `media-src` для этого не нужны, если файлы отдаются с нашего домена.
- Тесты: звук не играет без «Начать», выключенный звук не играет, пропуск останавливает звук.

> Выбор звука 2026-11-20: набор A из прототипа (`hyperframes-lab/sounds/SOURCES.md`), звуки по событиям таймлайна — без звука на уменьшении лого; сигнал — `computerNoise_000` 1,1 с с затуханием. Подложки пока нет.

### 7. Встраивание в IntroPlayer [medium]
- Новый проп `introTheme?: ThemeKey | null` (по умолчанию `null`: поведение как сейчас, старые тесты и `IntroPreviewPage` с `?src=` не меняются). Проп `theme: 'night' | 'light'` оставляем, тон темы кодом его перекрывает (`dark` → `night`), чтобы не ломать публичный API. Переименование — отдельным решением, если пользователь захочет.
- Фазы с темой кодом: `start` → «Начать» → `playing` (сцена играет) → `clean` → `done` (слот монтируется, начинается вылет). Видео не рендерится, кнопка звука скрыта (у темы кодом звука нет).
- **Полный экран:** «Начать» запрашивает Fullscreen API как сейчас. Таймлайн строится после того, как размер устоялся: ждать `fullscreenchange` или два `requestAnimationFrame`, размер корня брать через `ResizeObserver`. Изменение размера во время `playing` (поворот телефона, выход по Esc) = «Пропустить»: сразу `clean`, таймлайн на лету не пересчитывается. На iOS Safari кнопки полного экрана нет (как сейчас), высота уже через `dvh`.
- **«Пропустить»:** `scene.skip()` → `finish()`. На стартовом экране (`skippable`) — сразу `done` со сценой в `clean`.
- **«Пропустить» со стартового экрана** (`PlayPage` передаёт `skippable`, у ученика кнопка есть сразу) ведёт в `done` со сценой в `clean` и **тоже запускает фирменный вылет**: загрузка gsap не привязана к «Начать», полный экран в этом пути не запрашивается.
- **Скрим** (`.intro-player__scrim`, `v-if="phase === 'done'"`) сейчас появляется ровно в момент шва и приглушает сигнал (0,65–0,85 ночного тона), а рамка в слоте остаётся яркой — стык виден. Решение — вопрос 11: (а) у тем кодом скрима нет или он легче (палитра чистой сцены уже рассчитана на AA; это отступление от ADR 0014); (б) скрим остаётся, сигнал рисуется отдельным слоем над скримом и под содержимым слота, новый токен `--z-player-signal` в каскаде `global.scss`.
- **Reduced motion:** при `prefers-reduced-motion: reduce` «Начать» ведёт сразу в `done`, сцена в `clean`, gsap не загружается.
- Статичный `.intro-player__pcb` скрыт при теме кодом: плата сцены его заменяет, иначе узор двоится.
- Слой сцены — сосед слота внутри корня, позади скрима и слота. `transform`, `filter`, `contain`, `backdrop-filter` на корне и слоте по-прежнему запрещены (ADR 0014). Если нужен свой `--z-*`, он встаёт в каскад `global.scss`.
- `provide(PLAYER_ENTRANCE_KEY, …)`: контекст вылета (вид вылета по теме и reduced motion, флаг «уже был», `signalTo`, перевод координат DOM в систему корня проигрывателя).
- **Точка сохранения:** перед шагом (публичный API виджета, `features/play-session`, `entities`).
- **Тесты:** новый `introPlayerTheme.nuxt.test.ts` (gsap и сцена замоканы): «Начать» → `playing` → `clean` → `done`, слот появляется только после `clean`; «Пропустить» в `playing` даёт мгновенный `done`; reduced motion → `done` сразу, загрузчик gsap не вызывался; без `introTheme` всё как раньше; статичная плата скрыта при теме кодом; размонтирование посреди `playing` чистое (нет ошибок, `revert` вызван). Старый `introPlayer.nuxt.test.ts` не правится.
- **Критерий:** на `/intro-preview?theme=nataskium-dark` полный цикл, «Пропустить» мгновенный, полный экран без рывка сцены.

## Риски и пограничные случаи
- **Миграций Prisma нет**, API и `packages/shared` не меняются (кроме варианта вопроса 9), выбор темы на сервер не уходит. Данные учеников не собираются и не сохраняются.
- **Таймер задания** стартует при монтировании игры, значит вылет (1–2,5 с) съедает время задания с лимитом. Монтировать игру раньше нельзя: это нарушит «таймер стартует после интро» (ADR 0014). См. вопрос 6.
- **Расхождение длительности:** ADR 0015 говорит «вылет около 1 с», в прототипе сигнал 1,1 с плюс рамка и варианты около 1,3 с. См. вопрос 8.
- **Рамка карточки против ADR 0014** («игра без подложки, белой панели нет»): постоянная рамка меняет вид викторины. См. вопрос 3.
- **Полный экран и ресайз:** «Начать» меняет размер контейнера. Если таймлайн строится до того, как размер устоялся, раскладка съедет. Ресайз во время интро = пропуск.
- **`position: fixed`** летящей плитки ломается от `transform`, `filter` или `contain` на любом предке, а не только на контейнере и слоте.
- **Слабые телефоны и Chromebook:** маски платы статичны, анимируются только `opacity`, `transform` и штрихи SVG; без `filter: blur` и `drop-shadow`. Обязательна проверка с CPU ×4–×6 в DevTools и на реальном слабом Android.
- **iOS Safari:** нет Fullscreen API для блока (кнопка скрыта); проверить `pathLength` у обводки, `dvh`, `inert` (Safari 15.5+).
- **Утечки:** все твины в `gsap.context`, `revert()` в `onBeforeUnmount` у сцены и у вылета. `:key="view.kind"` пересоздаёт проигрыватель — это тоже должно проходить чисто.
- **SSR:** `/play/**` уже `ssr: false`, но gsap всё равно только через динамический импорт в `onMounted`. Сбой загрузки чанка → чистая сцена без анимации, игра доступна.
- **CSP** (`script-src 'self'` + hash по `architecture.md`): gsap не использует `eval` и `new Function`. Он пишет `element.style` через CSSOM, а CSP этого не ограничивает. Чанк с того же origin. Каталог тем только в коде, без загрузки из сети и без `v-html`. Ключ темы из `?theme=` в dev-странице сверяется с каталогом.
- **Копия путей лого** в `logoPaths.ts` может разойтись с `AppLogo.vue` при ребрендинге. `AppLogo` не трогаем; в `logoPaths.ts` указать источник путей и сверить на ревью.
- **Две платы** (статичная `pcb-white.webp` у проигрывателя и SVG-узор сцены) — статичная скрывается при теме кодом.
- **Лицензия GSAP** (Webflow Standard No Charge) не open source; запрещены только визуальные no-code конструкторы анимаций. Фиксируется в ADR 0015.
- **Тесты в happy-dom:** нет `getBBox`, `getTotalLength` и реального layout. Движение проверяется только в Playwright, unit-тесты проверяют договор.
- **Контраст:** вопросы на чистой сцене используют существующие `--g-*`. Светлый тон сцены (белый градиент) совпадает со светлым набором `--g-*`; проверить AA на самом ярком месте.
- **Скрим на шве** приглушает сигнал и появляется рывком (вопрос 11).
- **Телефон:** карточка сразу под полосой, маршрут прототипа обрезается без ограничения подъёма.
- **Анимации Ната** (`shared/nat/`) не затрагиваются.
