# Plan: Игры «Викторина» и «Сопоставление» внутри области проигрывателя интро

## Goal
Экран задания показывается ПОВЕРХ последнего кадра темы (пока тема не подключена — ночной фон #171B3A с узором платы, макет B), внутри области `IntroPlayer`, а не отдельной страницей рядом с ним.

## Что есть сейчас (факты из кода)
- `app/pages/play/[token].vue` → `PlayPage` (layout `play`: `AppHeader` + `main` + `AppFooter`, фон белый с узором платы). `PlayPage` делает один GET, по `type` выбирает `QuizPlay` / `MatchingPlay` (или «загрузка»). Оба виджета — `<section>` с `max-width: 560px`, белый фон страницы.
- `IntroPlayer` (`widgets/intro-player`): `div.intro-player` с `min-height: 100dvh`, `overflow: hidden`, фон `--color-night`, внутри `__pcb`, `<video>` (`absolute inset:0`, `object-fit: cover`), `__scrim` в фазе `done`, стартовая консоль, **слот по умолчанию показывается только в фазе `done`** (`__content`: `flex:1`, `position: relative`), верхняя полоса (`steps`, «Пропустить»), нижние кнопки (звук, полный экран, `absolute`, `bottom: 32px`, `right: 20px`). Фуллскрин запрашивается на корневой `div` (`rootRef.requestFullscreen()`), значит слот в нём остаётся видимым в фуллскрине. Пропсы: `src`, `poster`, тексты. Событие `done`. В `IntroPreviewPage` проигрыватель обёрнут вручную, к игре не подключён.
- Липкий лоток `MatchingBoard`: `position: sticky; top: var(--header-height); z-index: var(--z-matching-tray)`; отрицательные боковые поля `-var(--gutter)`; `DefinitionCard` использует `scroll-margin-top` под лоток, `html` имеет `scroll-padding-top` под шапку сайта.
- Автопрокрутка перетаскивания: `useMatchingDrag.scrollFrame` — `window.scrollBy`, зона `[низ лотка, window.innerHeight]`. Это жёсткая привязка к window как к прокручиваемому элементу.
- Слои: `--z-pre-footer(1) < --z-matching-tray(2) < --z-header(3) < --z-language-menu(4) < --z-drag-chip(5)`. Летящая плитка `matching-board__lifted` — `position: fixed` (координаты по `clientX/Y`).
- Таймер: `PlayTimer` внутри игры (у викторины под шапкой вопроса, у сопоставления в лотке), логика — `PLAY_TIMER_KEY` + `useQuizPlayTimer` / `useMatchingPlayTimer`. Старт таймера привязан к `store.start()` в `onMounted` виджета игры.
- Фокус: у викторины `heading.focus()` на `onMounted` и при смене вопроса/фазы; у сопоставления `heading.focus()` на `onMounted` и фокус на «Проверить»/следующее определение. `PlayResult` фокусирует свой `h1`.
- Тема в данных задания **не существует** (grep по `prisma/schema.prisma`, `packages/shared` — пусто). Роликов нет; `public/intro/test.mp4` не коммитится. CSP в `nuxt.config.ts`/docs/architecture.md: `media-src` не задан (см. п. 6).
- Нужны ли ADR: правила — `docs/adr/README.md`. Решение «интро + тема + игра внутри проигрывателя» — значимое → **новый ADR 0014** (см. шаг 1).

## 1. Что такое «область проигрывателя»

**Рекомендация:** область = корневой `div.intro-player`, он занимает **весь экран страницы задания** (`/play/:token`) и заменяет собой `layout play`-вёрстку для этой страницы: шапка и подвал сайта на странице задания **не показываются** (для ученика это «экран игры», а не сайт; лишние ссылки отвлекают и дают выход из задания). Это меняет layout страницы — вопрос пользователю (Q1).

- Размер: `100dvh × 100%` ширины, без своего соотношения сторон (mobile-first, телефон вертикально). Ролик: `object-fit: cover` (как сейчас): кадр обрезается по краям, важное в ролике — по центру; это требование к авторам роликов (Q8).
- Скролл: **внутри области** на отдельном контейнере слота (`overflow-y: auto`, `-webkit-overflow-scrolling` не нужен, `overscroll-behavior: contain`), а не скролл страницы. Причина: фон (кадр) должен стоять на месте, а задание листаться по нему; при скролле страницы пришлось бы держать фон `position: fixed`, а фуллскрин всё равно делается на корне. Следствие: корень `overflow: hidden`, высота `100dvh`, слот `flex: 1; min-height: 0; overflow-y: auto`.
- Фуллскрин: на корневой `div` (уже так) — слот и игра остаются внутри, ничего менять в API не надо. Кнопки управления (звук/полный экран) в фазе `done` остаются только «полный экран» (звук без видео не нужен, уже так: `v-if="phase === 'playing'"`).
- Дев-режим «в уменьшенной рамке» (десктоп): макет на мобильной раскладке; на широких экранах — та же область на весь экран, содержимое слота центрируется `max-width: 560px` (как сейчас у игр). Tablet/desktop-вёрстка — только по запросу (память `mobile-first-only`).

## 2. Слои и владение фоном

Порядок снизу вверх внутри `IntroPlayer` (z-index внутри корня, корень создаёт `isolation: isolate`):
1. Фон-цвет `--color-night`.
2. Узор платы (`__pcb`) — виден, пока нет кадра темы.
3. `<video>` (только когда есть `src`; последний кадр остаётся после `ended`/skip).
4. Скрим (`__scrim`) — затемнение под игрой, чтобы белые карточки/текст читались на любом кадре (контраст игры гарантируется скримом, а не темой).
5. Слот игры (`__content`, скроллится).
6. Верхняя полоса (шаги, «Пропустить») и нижние кнопки — всегда сверху.

**Владелец фона — `IntroPlayer`.** Игры (`QuizPlay`, `MatchingPlay`) фон не рисуют (убрать зависимость от белого фона `play-layout`: сейчас их цвета рассчитаны на белое — см. шаг 5 про «читаемость на тёмном»).

**Слот и размеры.** Слот отдаёт игре размеры не через props, а через CSS: контейнер слота — `container-type: size` не нужен; достаточно, чтобы слот был скролл-контейнером, а игры брали высоту у родителя (`min-height: 100%`). Для кода, которому нужны числа (автопрокрутка), — ссылка на элемент прокрутки (см. п. 4): `IntroPlayer` делает `provide` ключа `PLAYER_SCROLL_KEY` (ref на элемент слота) в `widgets/intro-player`; игры инжектят его, а если не вложены (тесты, превью) — используют `window`. Импорт `widgets → widgets` запрещён FSD → ключ должен лежать на уровне ниже: **`features/play-session`** (там уже `PLAY_TIMER_KEY`) — ровно то же место, ровно тот же приём. `IntroPlayer` импортирует из features (разрешено, сверху вниз).

**Кто собирает.** Игровые виджеты не импортируют `IntroPlayer` (виджет → виджет нельзя). Собирает `PlayPage` (страница): `<IntroPlayer ...><QuizPlay/MatchingPlay/></IntroPlayer>`.

## 3. Тема

- **Пока:** тема — константа «тема по умолчанию» (ключ `'default'`) в `entities` или `shared` (например, `shared/lib` / новый `entities/theme`): `{ key, videoSrc: null }`. `videoSrc === null` → `IntroPlayer` не рисует `<video>`, пропускает фазу `playing` (кнопка «Начать» ведёт сразу к заданию — логика `isVideoUnavailable` уже есть) и показывает ночной фон с узором (макет B).
- **Потом:** поле темы в задании (`theme` ключом, а не адресом: сервер отдаёт только ключ из белого списка, клиент мапит ключ → `src`). Это **миграция Prisma = высокий риск**; **в этот план не входит**. Решение по данным — после появления роликов (Q3).
- Формат/хранение роликов — **не придумываю**: в памяти `intro-player-decisions` предложен Яндекс Object Storage (Range, `media-src` в CSP, загрузка вручную), окончательное решение отложено. Остаётся открытым вопросом.
- Подстановка кадра: ничего отдельного не нужно — последний кадр остаётся от `<video>` (`currentTime = duration` в `skip`). Для превью-кадра до старта можно позже передавать `poster`. Первый кадр на iOS Safari иногда не показывается (нужно проверить, когда появятся ролики).
- Тексты стартового экрана для игры: `typeLabel` («Викторина»/«Сопоставление»), `title` — название задания, `hint` — пояснение. Сейчас строки захардкожены в `IntroPreviewPage` (русский) → в продакшене **через i18n** (ru/en/de/fr, ключи в `shared/i18n/locales/*.ts` — перезапуск web-контейнера после правки, память `i18n-dev-no-hmr`). Названия типа/подсказки нужны на 4 языках.

## 4. Что меняется в `PlayPage`, `QuizPlay`, `MatchingPlay`

### PlayPage (`src/pages/PlayPage.vue`)
- Сейчас рендерит игру напрямую. Станет: после GET (`view` не `loading`) рендерит `IntroPlayer` с игрой в слоте.
- **Ключевой вопрос порядка:** `QuizPlay`/`MatchingPlay` вызывают `store.start()` в `onMounted`, запускающий таймер. Слот `IntroPlayer` монтируется только в фазе `done` (`v-if`) → таймер стартует после интро. Это **правильно** (время интро не должно входить в лимит) — оставляем.
- Состояния «не найдено / ошибка загрузки / невалидный токен»: показываются сейчас самой игрой (`notFound`, `failed`). Интро для них показывать **не надо** (нет названия задания). Для `loadView` ошибок и невалидного токена: игра рендерится без обёртки (как сейчас), либо в той же области на тёмном фоне. Рекомендация: без интро, но на фоне области (единый вид, без белой вспышки) — решает дизайнер в макете.
- Режим предпросмотра учителя `?preview=1` (`PREVIEW_QUERY_KEY`): учитель смотрит задание из кабинета — интро нужно ему показать или пропустить? Рекомендация: **показывать «Пропустить» как обычно, плюс** кнопка «Назад» остаётся внутри слота (ловится `isPreview`). Q4.
- `useSeoMeta` остаётся в PlayPage/виджетах без изменений.
- Название задания для стартового экрана доступно из `view.initial` (ответ GET) — отдельный запрос не нужен.

### QuizPlay (`QuizPlay.vue`)
- Убрать `max-width/padding` у корня? Оставить как внутренний столбец слота (`max-width: 560px`, `margin: 0 auto`). Менять пока минимально.
- Цвета: сейчас текст `--color-text` на прозрачном фоне страницы (белая). На тёмном фоне/скриме текст станет нечитаем → **либо** весь игровой столбец кладётся на белую «карточку-консоль» (внутри слота: `background: --color-white; border-radius`, как в `intro-preview-page__banner/cards`), **либо** все цвета инвертируются. Рекомендация: **белая панель** — не трогает ~40 цветовых решений вопросов/ответов/итога, контраст сохраняется. Это решение для макета (Q5).
- Фокус: `heading.focus()` в `onMounted` — к тому моменту фаза `done` уже началась, слот смонтирован → фокус ставится как сейчас. Но **при переходе интро → слот** фокус был на кнопке «Начать»/«Пропустить», которая исчезает; `heading.focus()` его перехватит — ок. Проверить, что `heading.focus()` не вызывает скролл слота (`preventScroll` не нужен, он в начале).
- Таймер: без изменений по логике; `aria-live` объявление (`quiz-play__sr-only`) остаётся.

### MatchingPlay (`MatchingPlay.vue` + `MatchingBoard.vue` + `useMatchingDrag.ts`)
Здесь основная работа.
- **Липкий лоток:** `position: sticky; top: var(--header-height)` привязан к шапке сайта. Шапки на странице больше нет (п. 1) → `top: 0` относительно скролл-контейнера слота. Заменить `var(--header-height)` на переменную `--play-sticky-top` с дефолтом `0` (чтобы лоток под верхней полосой интро — «шаги» + «Пропустить» — не перекрывался: полоса `absolute` над слотом, ~88px высотой → слоту нужен `padding-top` под полосу, а лотку `top` = высота полосы? Лучше: верхняя полоса интро в фазе `done` **убирается/сжимается** (в `done` «Пропустить» не нужен, есть только шаги). Решает дизайнер (макет), см. Q6). Параметр — CSS-переменная, которую задаёт слот.
- **Отрицательные поля лотка** (`margin: 16px calc(-1 * var(--gutter))`) рассчитаны на `padding` секции `matching-play`. Сохраняются, если секция остаётся тем же столбцом внутри слота.
- **z-index:** `--z-matching-tray` стоит ниже `--z-header`; теперь шапки нет, но верхняя полоса интро (`__top`) и кнопки — сверху слота. Нужны новые токены в `global.scss` (каскадом `calc(var(--предыдущий)+1)`): слои интро (`--z-intro-content`, `--z-intro-controls`) выше `--z-matching-tray` (лоток — внутри слота, создаёт свой контекст, т.к. корень `isolation: isolate`). Летящая плитка `--z-drag-chip` **должна быть выше всего интро** — остаётся `position: fixed` вне контекста? Нет: `position: fixed` внутри предка с `transform/filter/contain` ломается. Корень и слот **не должны** иметь `transform`, `filter`, `contain`, `will-change: transform`, `backdrop-filter` (иначе fixed-плитка поедет). Заложить в критерий успеха. Анимация `Transition` с `opacity` (fade) безопасна.
- **Фуллскрин:** плитка `position: fixed` внутри элемента в фуллскрине рисуется верно (top layer — корень; fixed считается от viewport). Проверить в Chrome и Safari (Q7: Safari iOS полноэкранный режим для `div` не поддерживается — `document.fullscreenEnabled` там false → `canFullscreen` false, кнопка скрыта; уже учтено).
- **Автопрокрутка (`useMatchingDrag`):** сейчас `window.scrollBy` и `window.innerHeight`. Нужна параметризация: опция `scrollContainer` (ref на элемент слота из `PLAYER_SCROLL_KEY`, иначе `null` = window). Зона: `bottom` = `container.getBoundingClientRect().bottom` (или `window.innerHeight`), `top` = низ лотка; шаг — `container.scrollBy(0, step)`. Чистая функция `autoScrollStep` не меняется (её тесты `dragGeometry.test.ts` остаются). `hitTarget` считает по `getBoundingClientRect` — не зависит от контейнера.
- **Касания:** `touch-action` и `preventDefault` в `onMove` (passive: false на window) — работают; но слот с `overflow-y: auto` будет сам скроллиться пальцем, а перетаскивание `preventDefault` отключает прокрутку на время жеста — как сейчас.
- **`scroll-margin-top`** у `DefinitionCard` и `scroll-padding-top` у `html`: перенести `scroll-padding-top` на слот (иначе фокус с клавиатуры уйдёт под лоток).
- **Фокус:** `heading.focus()`, `checkButton.focus({ preventScroll: true })`, `cards[i].focus()` — работают внутри слота без изменений.
- **Таймер в лотке:** остаётся.
- **Итог (`MatchingResult`, `PlayResult`):** внутри слота, листается там же. Кнопка «Пройти ещё раз» → `store.start()`: интро не показываем заново (интро — один раз за загрузку страницы). Q9.

Только mobile-first: 360–430 px. Проверить: iPhone Safari (динамическая адресная строка — поэтому `100dvh`, не `100vh`; уже так), клавиатура не вызывается. Полноэкранный режим на iOS для div недоступен — кнопки нет, область остаётся «весь экран страницы» без панели браузера не скрыть; приемлемо.

## 6. Безопасность
- `src` ролика: только из белого списка ключей темы → адреса своего origin (как `SAFE_SRC` в `IntroPreviewPage`: `^\/intro\/...`, без `..`). Не принимать `src` из запроса/ответа API в продакшене; `IntroPreviewPage` с `?src=` остаётся dev-only (`DEV_ONLY_PATHS` в `nuxt.config.ts`).
- Тема приходит ключом из ответа GET (позже) → клиент валидирует Zod (enum известных ключей), неизвестный ключ → тема по умолчанию.
- **CSP `media-src`**: сейчас не задан (значит действует `default-src`; если `default-src 'self'`, свои `/intro/*.mp4` работают). При внешнем хранилище (Yandex Object Storage) нужно добавить origin в `media-src` **перед деплоем** и добавить пункт в docs/architecture.md (рядом с `img-src`) и в память «к деплою». Без роликов CSP не менять.
- Полный экран/автозвук: звук включается по жесту «Начать» (уже так).
- Ученические данные не затрагиваются: ничего не сохраняется (результаты не хранятся — продуктовое правило не нарушается).
- Новые зависимости: **не нужны** (видео — нативный `<video>`).

## Risks & Edge Cases
- `position: fixed` летящей плитки ломается от `transform/filter/contain` на предках — запретить в IntroPlayer и слоте.
- Автопрокрутка завязана на `window` — без параметризации после перехода на скролл-контейнер перестанет работать (главный регресс).
- iOS Safari: нет Fullscreen API для div; `100dvh`; первый кадр видео без `poster`; autoplay со звуком — по жесту «Начать» (уже решено).
- Таймер не должен идти во время интро (монтирование слота только в `done` — сохранить).
- Тёмный фон + белая панель: контраст ролика/кадра темы любой → скрим обязателен.
- Бэк/«Назад» в предпросмотре учителя, ошибка загрузки, невалидный токен — отдельные состояния без интро.
- Reduced-motion: интро пропускается (логика есть); fade перехода отключён (есть).
- Незакоммиченные правки в `locales/*.ts` и `LibraryGroupTiles.vue` — не затирать.
- Один и тот же `store` игры при «Пройти ещё раз» — интро повторно не показываем.
- Анимации Ната не затрагиваются.
- Prisma-миграции в плане **нет**; поле темы в задании — отдельное решение (высокий риск).
