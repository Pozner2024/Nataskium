# 0019. Задание из библиотеки открывается игрой

- **Статус:** Принято
- **Дата:** 2026-11-24

## Контекст
Клик по заданию в библиотеке открывал карточку со списком вопросов (`GET /api/library/:number`): у викторины
первые 5 вопросов без ответов, у сопоставления все определения и слова, у «да/нет» тексты утверждений.
Учитель хочет не читать список, а пройти задание, как в Wordwall, и потом решить, брать ли его себе.
Игра работает только по `shareToken`, а он в публичные ответы библиотеки не попадает (ADR-0002).

## Решение
- `/library/quiz/<номер>-<slug>` показывает саму игру в проигрывателе интро (ADR-0014). Учитель проходит её так же,
  как ученик: оценка в конце, без пометок «пробное».
- Публичные маршруты `/api/library/play/<номер>` повторяют `/api/play/<shareToken>`: `GET`, `POST /check`,
  `POST /finish`, `POST /matching/finish`, `POST /true-false/check`, `POST /true-false/finish`. На каждом запросе сервер
  находит `shareToken` по номеру среди опубликованных заданий (то же условие публичности, что у списка и «Взять себе»)
  и вызывает те же use-cases игры без изменений. `shareToken` клиенту не отдаётся.
- Невалидный номер и неопубликованное, скрытое модерацией или удалённое задание дают тот же 404 и то же тело
  (`Quiz not found`), что и `/api/play`.
- Лимитеры общие с `/api/play` (одни экземпляры в `app.ts`): один бюджет на IP.
- `GET /api/library/:number` (карточка) удалён вместе со схемами карточки в `packages/shared` и `LIBRARY_PREVIEW_QUESTIONS`.
- «Взять себе» переезжает на карточку списка.
- Язык игры из библиотеки не переключается по браузеру: адрес библиотеки уже содержит язык.
- Код: резолвер `findLibraryShareToken` и роутер `libraryPlayRoutes.ts` в `features/library`; функции игры приходят
  в роутер через deps из `app.ts`, фича library фичу play не импортирует.

## Последствия
- **Главное.** Правильные ответы заданий из библиотеки, в том числе заданий с оценкой, теперь может получить любой
  аноним по публичному последовательному номеру, без `shareToken` и без аккаунта: через `check` и review в `finish`
  при `showAnswers` либо подбором через `finish` (риск подбора уже принят для `/play`). Раньше для этого нужен был
  секретный `shareToken` или аккаунт учителя («Взять себе»). Принято пользователем 2026-11-24; use-cases игры
  не меняются.
- Публичность проверяет только резолвер: use-cases игры отбрасывают лишь удалённые задания. Любой новый маршрут игры
  из библиотеки обязан идти через `findLibraryShareToken`, иначе обойдёт `is_public` и модерацию.
- Между поиском токена и запросом игры задание могут снять с публикации: один такой запрос проскочит. Окно — миллисекунды,
  содержимое было доступно мгновением раньше.
- Бюджет лимитов на IP общий для игры по ссылке и игры из библиотеки: класс за NAT, который играет в оба, тратит один лимит.
- Адрес игры из библиотеки пока `noindex`: его ставят виджеты игр (ADR-0011).

## Связи
- Уточняет **ADR-0002**: фраза «публичный ответ библиотеки не содержит правильных ответов» не относится к маршрутам игры
  `/api/library/play/*`; `shareToken`, id задания и данные автора по-прежнему не отдаются.
- Уточняет **ADR-0013**: раздел о карточке библиотеки (`LIBRARY_PREVIEW_QUESTIONS`, карточка сопоставления) больше не действует.
- Уточняет **ADR-0005**: меняется только место кнопки «Взять себе».
- Опирается на **ADR-0014**. ADR-0007 не меняется.
- Ни один принятый ADR не заменяется целиком, их статусы не меняются.

## Отвергнутые варианты
- **Отдавать `shareToken` в ответе библиотеки.** Нарушает ADR-0002 и раскрывает ссылку для класса.
- **Редирект на `/play/<shareToken>`.** Раскрывает токен в адресе.
- **Оставить карточку и добавить кнопку «Играть».** Лишний шаг; решение пользователя.
