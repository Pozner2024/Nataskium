# 0011. SEO делаем в конце проекта, перед публичным запуском

- **Статус:** Принято
- **Дата:** 2026-11-16
- **Уточняет:** [ADR-0007](0007-library-public-page.md) (срок серверной отрисовки)

## Контекст
По ADR-0007 серверная отрисовка библиотеки — следующий шаг после первой версии страницы. Шаг 10 плана
библиотеки объединял публичные страницы и SEO: SSR, `swr`, meta-теги, canonical, 301 по slug, sitemap, robots.

Пользователь предложил перенести SEO в конец проекта. Причины: страницы, адреса и содержимое ещё меняются,
и SEO, сделанное раньше, придётся переделывать. Смена адресов после индексации дорогая: редиректы, потеря позиций.

## Решение
- SEO делается **последним** шагом перед публичным запуском, после того как функциональность проекта собрана.
  Для библиотеки это шаг 13 плана `.claude/plans/library.md`.
- В этот отложенный блок входят:
  - серверная отрисовка публичных страниц библиотеки и SSR-режим `apiClient` с `runtimeConfig`;
  - `swr`-кэш на страницах;
  - meta-теги, `canonical`, OG, 301 по slug;
  - `noindex` для страниц поиска (`?q=`);
  - `sitemap.xml` (данные — `GET /api/library/sitemap`) и `robots.txt`.
- До этого шага адреса публичных страниц фиксируются: `/library`, `/library/<группа>`, `/library/quiz/<номер>-<slug>`.
  Менять их после начала индексации нельзя без редиректов.
- Дополнительную защиту `/play/<shareToken>` от индексации (`robots.txt`, `X-Robots-Tag`) не вводим: пользователь
  счёл её лишней. Остаётся то, что уже есть на странице.

## Последствия
- До SEO-этапа страницы библиотеки рендерятся в браузере, поисковики их не индексируют. Для разработки это
  безопасно; перед публичным запуском — нет.
- Серверная отрисовка меняет сетевой путь: запросы Nuxt к API идут с IP контейнера web. Поэтому
  проброс `X-Real-IP` и `TRUSTED_PROXY_IPS` остаётся в деплое, а не в SEO-этапе: без него лимиты по IP
  бьют по всем посетителям сразу.
- Поздний SSR затронет уже написанный `apiClient` и `runtimeConfig`. Это принимаем, потому что эти части
  изолированы и покрыты тестами.

## Отвергнутые варианты
- SEO сразу, в шаге 10 плана — отвергнуто: переделки при каждом изменении страниц.
- Не делать SEO вообще — отвергнуто: библиотека задумана как публичная, открытая для поиска.
- SEO отдельным проектом после запуска — отвергнуто: после запуска адреса и индексация уже живут, переход
  становится дороже.
