# 0012. Таймер задания

- **Статус:** Принято
- **Дата:** 2026-11-16

## Контекст
Учителю нужен таймер в задании. Результаты не сохраняются, сессий и состояния игры на сервере нет: сервер только проверяет ответы и возвращает `{ percent, grade }`.

## Решение
- Три режима: **без таймера** (по умолчанию), **секундомер** (время растёт, на результат не влияет), **лимит времени** на всё задание.
- Лимит — `1–180` минут, хранится секундами (`MIN_TIME_LIMIT_SECONDS = 60`, `MAX_TIME_LIMIT_SECONDS = 10800`, по умолчанию при включении 600). Интерфейс работает в минутах.
- Таймер — часть настроек задания: в Zod одно поле `timer` (union по `mode`, секунды есть только у `limit`), в базе две колонки `timer_mode` и `time_limit_seconds` с двумя CHECK, которые дублируют инвариант. Старые клиенты без поля сохраняют задание без таймера.
- Таймер копируется при «Взять себе». В публичной карточке и списке библиотеки не показывается.
- Значение лимита публично и не секретно: приходит в `GET /api/play/:token` вместе с заданием.
- Отсчёт идёт на клиенте от показа первого вопроса. По истечении лимита игра завершается сама: неотвеченные вопросы дают 0 баллов, выбор текущего вопроса, не отправленный к концу времени, не засчитывается.
- `POST /finish` принимает пустой массив в `answers[i]` как «не отвечено» (0 баллов за вопрос), непустой проверяется строго, как раньше. `POST /check` остаётся строгим. Формат протокола не меняется.
- Процент и оценка считаются только по проценту правильных ответов; скорость на оценку не влияет.

## Последствия
- Отсчёт идёт по системным часам устройства (`Date.now()`): так он не отстаёт в фоновой вкладке и после сна. Цена: резкий скачок часов вперёд (синхронизация времени, смена времени вручную) досрочно завершит игру и честному ученику. Принято: для школьной игры редкий случай, а монотонные часы на спящем телефоне останавливаются и дают обратную ошибку.
- Лимит соблюдает только клиент: ученик может остановить таймер (DevTools, офлайн, подмена часов) и сдать позже. Серверного ограничения нет: оно потребовало бы сессий и состояния на сервере, что противоречит «результаты не сохраняются». Для оценок это слабое место; если появятся «контрольные», решение пересматриваем новым ADR (возможный вариант — HMAC-токен старта `{shareToken, startedAt}` без БД).
- Пустой ответ в `finish` не даёт ученику выгоды (0 баллов), поэтому ослабление проверки безопасно.
- Миграция аддитивная: существующие строки получают `none` / `NULL`.
- Персональных данных не добавляется.

## Отвергнутые варианты
- Лимит на каждый вопрос.
- Серверный таймер с токеном старта: новый эндпоинт, новый шаг протокола, расхождение часов.
- Штраф или бонус за скорость: оценка только по проценту.
- Таймер в публичной карточке библиотеки.
- Отдельная таблица настроек таймера и JSON-поле `settings`: две колонки с CHECK проще и защищены базой.
