# 0015. Темы интро: выбор учителем, смена учеником, темы кодом и темы-ролики

- **Статус:** Предложено
- **Дата:** 2026-11-20

## Контекст
[ADR-0014](0014-play-inside-intro-player.md) положил игру поверх последнего кадра ролика и прямо отложил тему «отдельным ADR»:
ключ темы, формат и хранение роликов. Теперь нужна не одна тема, а много (фирменная Nataskium, космос и другие),
тему задания выбирает учитель, а ученик при желании может сменить её перед стартом. Пробы в `hyperframes-lab` показали:
- анимация (карточки, галочка, конфетти) собирается кодом в HyperFrames за один рендер, но вшивать её в каждый ролик значит
  перемножать файлы (темы × типы игр), а прозрачное видео (WebM с альфой) ненадёжно в Safari на iPhone;
- фирменное интро (`work/brand-intro`: робот-«а» из логотипа, буквы Nataskium, узор платы) — это HTML, SVG и GSAP.
  Его можно играть прямо в браузере, а не рендерить в MP4. Тогда интро и первый вопрос живут в одной сцене без шва.

Решение 2026-11-16 «CSS/SVG-пилот примитивен, нужны ролики» пересмотрено: прототип на коде пользователь приняла.

## Решение
- **Тему задания выбирает учитель**, ключ темы хранится в задании (миграция базы, ключ проверяется на сервере схемой
  из `packages/shared`). Если учитель тему не выбрал, играет **тема по умолчанию**.
- **Ученик может сменить тему** на стартовом экране до «Начать». Его выбор живёт только на устройстве, на сервер
  не уходит и **не запоминается**: в следующий раз снова тема учителя.
- Вид и место выбора темы (у учителя в редакторе и у ученика на старте) **отложены**; до них все задания играют
  тему по умолчанию, миграция делается вместе с выбором у учителя.
- **Тема бывает двух видов:**
  - **тема кодом** — интро это Vue-компонент с анимацией на GSAP. У такой темы **свой вылет первого вопроса**,
    продолжающий её интро (у Nataskium сигнал по дорожке платы рисует рамку карточки вопроса);
  - **тема-ролик** — интро это видео. Вылет первого вопроса **общий** для всех роликов, в коде, цвета из `--g-*`;
    его делаем вместе с первым роликом, до тех пор вылет есть только у темы Nataskium.
- **Общий договор для любой темы:**
  - интро заканчивается **чистой сценой темы**: фон, на котором живут вопросы, без текста и персонажа в центре;
    центр свободен под карточку вопроса. Для ролика это его последний кадр, для темы кодом — финальное состояние сцены;
  - вылет первого вопроса начинается сразу по окончании интро (длительность задаёт тема; у Nataskium как в прототипе,
    около 3,3 с), вариант можно нажать, как только он
    приземлился. Анимируются только элементы карточки, не контейнер и не слот: запрет `transform`, `filter`
    на них из [ADR-0014](0014-play-inside-intro-player.md) остаётся. Вылет только у первого вопроса, дальше вопросы
    сменяются коротко;
  - «Пропустить» мгновенно приводит интро к чистой сцене и запускает вылет;
  - при `prefers-reduced-motion` интро не играет: сразу чистая сцена, вопрос появляется плавным проявлением;
  - после вылета фокус на тексте вопроса;
  - **таймер задания стартует после приземления вопроса**, вылет не съедает время задания;
  - скрим из [ADR-0014](0014-play-inside-intro-player.md) остаётся; сигнал и рамка темы кодом рисуются слоем над скримом;
  - **отступление от [ADR-0014](0014-play-inside-intro-player.md):** «Начать» не разворачивает проигрыватель на весь экран,
    полный экран включается только кнопкой «На весь экран» (решение пользователя 2026-11-21, для всех интро, в том числе роликов).
- **Тон темы выбирает палитру игры.** Набор `--g-*` берётся по тону (`dark` или `light`) ([ADR-0014](0014-play-inside-intro-player.md)),
  код игр не меняется.
- **Каталог тем лежит в репозитории** (ключ, вид, тон, для роликов — варианты и адреса файлов, для тем кодом — компонент),
  в виде кода с проверкой схемой (Zod). Каталог **не** загружается из хранилища: подмена файла в бакете позволила бы
  вставить свои стили или адреса на страницу детей.
- **Темы кодом:**
  - **GSAP** (`gsap`, точная версия 3.x, проверен 2026-11-20: без зависимостей и install-скриптов, `npm audit` чист).
    Лицензия Webflow «Standard No Charge» — не open source: коммерческое использование разрешено, запрещены визуальные
    no-code конструкторы анимаций, конкурирующие с Webflow;
  - сцена адаптируется под контейнер (телефон, 4:3, 16:9) раскладкой, а не обрезкой кадра;
  - анимируются `transform` и `opacity`; `filter: blur` и частицы — экономно, проверка на слабом телефоне обязательна;
  - шрифты Unbounded и Onest уже есть на сайте, отдельных файлов не нужно;
  - HyperFrames остаётся мастерской прототипов вне приложения: прототип переносится в Vue вручную.
- **Темы-ролики:**
  - у темы несколько вариантов: ролик, постер и тон; вариант выбирается случайно при каждом запуске;
  - ролики и постеры лежат в Яндекс Object Storage, в **отдельном бакете** только для тем: публичное чтение, запись только
    наша, отдельный сервисный аккаунт с минимальными правами. Имена файлов с хешем содержимого (`space-1.3f9a.mp4`),
    долгий неизменяемый кеш. Загружается только выбранный вариант;
  - проверка контраста при добавлении варианта: скрипт берёт последний кадр, считает яркость самого светлого места и сверяет
    с палитрой тона по правилу AA; не прошедший проверку вариант в каталог не попадает;
  - ролики собираются вне приложения (HyperFrames в изолированном контейнере, ИИ-клипы или сток);
  - CSP: `media-src` и `img-src` получают адрес бакета тем, запись в `docs/architecture.md` рядом с `img-src`.
    Бакет и CSP нужны, только когда появится первая тема-ролик.
- **Первые темы — фирменные «Nataskium ночь» и «Nataskium день», кодом**: одна анимация, два тона (тёмный и светлый
  отдельными темами, без переключателя тона). «Nataskium ночь» — тема по умолчанию. Вместе с вылетом около 8,5 с: на фоне платы по углам появляется
  робот-«а» и оживает, уезжает в конец слова и на обратном пути проявляет буквы Nataskium (вспышка контура, затем заливка),
  лого растворяется в чистую сцену, сигнал по дорожке приходит к карточке и рисует рамку первого вопроса. **Рамка карточки вопроса остаётся** после вылета (только в этой теме), с тремя точками окна.
- **Экран задания (для всех типов заданий, нынешних и будущих), решение пользователя 2026-11-21:** названия задания
  и полосы прогресса на экране игры нет; счётчик «N / всего» (со стрелками, где они есть) стоит внизу по центру под
  заданием и проявляется вместе с карточкой. Полосы игры из [ADR-0014](0014-play-inside-intro-player.md) нет совсем:
  таймер на телефоне в левом верхнем углу (на широком экране — в колонке слева), кнопки звука и полного экрана в игре —
  в правом верхнем углу (на старте и во время интро — в правом нижнем), плоские контурные.
- **Смена вопроса:** у темы кодом своя (у Nataskium импульс пробегает по рамке со звуком, элементы появляются по очереди),
  у остальных тем — перелистывание; при reduced motion — проявление. Содержимое обновляется на месте, фокус не теряется.
- **Звуки ответа** из набора темы: выбор варианта, верный и неверный ответ (только если учитель показывает ответы).
  «Пропустить» обрывает звук интро, звуки игры работают; кнопка звука есть и во время игры.
- **Звук темы — набор**: короткие звуки к событиям анимации и более длинные подложки там, где нужно; запускаются
  из таймлайна. Включается по «Начать», уважает кнопку звука, при пропуске и reduced motion не играет. Источник и лицензия
  (коммерческое использование, содержание для детей) записываются для каждого файла.

## Последствия
- Первую тему можно сделать без бакета, CSP для видео и скрипта контраста: они нужны только темам-роликам.
- Тема кодом легче ролика (десятки килобайт), чёткая на любом экране, может показать название задания и язык интерфейса.
- Новая зависимость `gsap` в `apps/web`; лицензия Webflow может меняться для будущих версий (старые остаются на прежних
  условиях). Если когда-нибудь учителям дадут визуальный конструктор анимаций на GSAP — лицензию пересматриваем.
- Тема кодом — это код в репозитории: каждая новая такая тема проходит ревью и тесты, авторы роликов её не сделают.
- Работа сейчас: каталог тем и схема ключа в `packages/shared`, перенос фирменного интро в Vue, вылет темы Nataskium
  (викторина, «да/нет», сопоставление), старт таймера после вылета, звук, «Пропустить» и `prefers-reduced-motion`, тесты.
  Позже: выбор темы у учителя (миграция) и у ученика, общий вылет для роликов вместе с первым роликом.
- Тема по умолчанию меняет поведение всех заданий: существующие тесты страницы задания и e2e придётся дополнить интро
  (правка тестов — с разрешения пользователя).
- Риски: слабые телефоны и школьные Chromebook (анимация кодом тяжелее видео), синхронизация вылета с концом интро,
  контраст светлых тем, первый кадр видео на iOS без постера.
- Не решено:
  - откуда брать ролики (HyperFrames, ИИ-клипы, сток) и проверка лицензий на коммерческое использование и содержание для детей;
  - список следующих тем и сколько вариантов у тем-роликов;
  - вид и место выбора темы у учителя и у ученика, нужен ли предпросмотр;
  - какие звуки и откуда (подборка с проверкой лицензий);
  - допустимый вес ролика и длина (пробы: 0,3 и 1 МБ за 10 секунд).

## Отвергнутые варианты
- **Все темы только роликами:** между видео и игрой остаётся шов, вылет вопроса нельзя продолжить из интро,
  фирменное интро в MP4 тяжелее и мутнее кода.
- **Все темы только кодом:** темы из ИИ-клипов, стока и After Effects кодом не сделать.
- **Web Animations API без библиотеки:** нет лицензионного риска, но больше кода, и прототип пришлось бы переписывать, а не переносить.
- **Анимация вшита в каждый ролик (ffmpeg):** файлов темы × игры, название задания и цвета темы не подставить.
- **Прозрачное видео поверх фона:** ненадёжно в Safari на iPhone, нужна синхронизация двух видео, файлы тяжелее.
- **Каталог тем в хранилище (JSON в бакете):** подмена файла даёт вставку стилей на страницы детей.
- **Запоминать выбор ученика:** отклонено пользователем, ученик каждый раз выбирает заново.
- **Тему выбирает только ученик, без темы задания:** учитель не может задать настроение задания; отклонено пользователем.
- **Один выбор темы с переключателем тона:** для ученика два выбора вместо одного; тона сделаны отдельными темами.
