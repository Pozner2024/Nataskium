## Поведение

- **Пары 2–10.** «Удалить» удаляет сразу, без подтверждения (решение пользователя). При 2 парах кнопка неактивна, под списком — «Нужно хотя бы 2 пары — удалять пока нечего» (`aria-describedby`). При 10 парах неактивна «+ Добавить пару», под ней — «Добавлено 10 пар — это максимум». Новая пара сразу получает фокус в поле «Слово».
- **Ошибки:**
  - перед запросом форму проверяет `matchingInputSchema` на клиенте; на 400 с `issues` пути `pairs.N.term` / `pairs.N.definition` приходят с сервера;
  - **дубль подсвечивается в обеих парах:** схема отмечает только вторую пару, store находит все пары с тем же `matchingKey` и пишет «Такое слово уже есть в паре N» у каждой. Если дубль пришёл только с сервера, а клиент пару не нашёл, — «Такой текст уже есть в другой паре»;
  - сводка внизу: «Исправьте отмеченные поля в парах: 2, 3» (`role="alert"`). Фокус уходит на первое поле с `aria-invalid`. У карточки с ошибкой оранжевая рамка 3px;
  - 409 → «Достигнут лимит: не больше 100 заданий…» (`MAX_ACTIVITIES_PER_TEACHER`); прочие ошибки → «Не получилось сохранить».
- **Создание → `/teacher/matching/<id>`:** `navigateTo(…, { replace: true })` с `handoverId`, как у викторины. Новая страница не грузит задание заново.
- **Доступность:**
  - у каждого поля `<label for>`;
  - счётчик виден (`aria-hidden`), а полный текст «Слово пары 2: 5 из 60 символов» — в `aria-describedby`;
  - номер-бейдж `aria-hidden`, заголовок карточки — `h3` «Пара N»;
  - у «Удалить» `aria-label` «Удалить пару N»;
  - `prefers-reduced-motion` отключает переходы.
- **Масштаб как в макете:** поля 56px и 18px, название 60px и 20px, «Удалить» 48px, «+ Добавить пару» 64px, кнопки 56px.

## Как удалить тестового учителя

Учитель `test-matching@example.invalid` создан одной строкой `teachers` через psql. Пароль нигде не записан. Удаление вместе с его заданиями (FK `ON DELETE CASCADE`) и сессиями:

```sh
docker exec nataskium-db-1 psql -U nataskium -d nataskium \
  -c "DELETE FROM teachers WHERE email = 'test-matching@example.invalid';"
```

Проверка: `SELECT count(*) FROM quizzes q JOIN teachers t ON t.id = q.teacher_id WHERE t.email = 'test-matching@example.invalid';` → 0.
