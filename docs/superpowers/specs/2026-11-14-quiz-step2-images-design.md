# Викторина, шаг 2: картинки в вопросах и вариантах

Дата: 2026-11-14. Статус: на согласовании у пользователя.
Основа: шаг 1 — `docs/superpowers/specs/2026-11-13-quiz-step1-design.md` (всё, что там решено, остаётся в силе).

## Зачем

Викторина шага 1 — только текст. Учителям младших классов, языков, биологии, географии нужны вопросы вида «Где кошка?» с четырьмя фотографиями или «Что изображено?» с картинкой в вопросе. Без картинок викторина заметно уступает аналогам.

## Цели

- Учитель добавляет картинку к вопросу и к любому варианту ответа, заменяет и убирает её
- Сервис сам уменьшает и сжимает картинку — учителю ничего редактировать не нужно
- Картинки видны в редакторе, в предпросмотре и на странице задания

## Не цели

- Встроенный поиск картинок (решение пользователя: отказались)
- Съёмка камерой из редактора (решение пользователя: сначала фото, потом загрузка файла)
- Редактирование картинки (обрезка, поворот вручную)
- Описание картинки для скринридера (решение пользователя: поле не нужно; может быть добавлено позже без поломки данных)
- Несколько картинок у одного вопроса/варианта
- Картинки по внешней ссылке (URL) — только загрузка файла

## Анти-цели

- В хранилище попадает что-то, кроме проверенной сервером картинки (исполняемый файл, SVG со скриптом, «картинка» с вредоносным содержимым)
- Сервер падает или зависает на огромной/битой картинке («пиксельная бомба»)
- Картинки удалённого аккаунта учителя остаются в хранилище (GDPR)
- Учитель может прикрепить к своей викторине чужую картинку или произвольный внешний адрес
- Обрезается важная часть картинки на странице задания

## Решения пользователя

- **Где картинки:** у вопроса — одна необязательная; у каждого варианта — одна необязательная
- **Текст вопроса обязателен всегда.** Вариант ответа может быть только картинкой: у варианта должен быть текст, картинка или оба (пустой вариант — ошибка)
- **Как добавить:** выбрать файл (компьютер, галерея телефона), перетащить мышкой (drag & drop), вставить скопированную картинку (Ctrl+V / Cmd+V). На телефоне вставка из буфера может не работать — это допустимо
- **Файл:** до **15 МБ**; форматы JPEG, PNG, WebP, HEIC. Больше — сообщение «Файл слишком большой, максимум 15 МБ»
- **HEIC:** если `sharp` в стандартной сборке его не читает — не поддерживать, а показывать понятное сообщение (сохранить фото в JPEG). iPhone обычно сам отдаёт JPEG при загрузке через браузер
- **Сервис сам уменьшает картинку** до нужного размера (как в NatsDoll)
- **Отображение:** картинка показывается **целиком, без обрезки** (`contain`); в плитке варианта — светлые поля вокруг вытянутых картинок. Картинка вопроса — целиком, над вариантами. Макет: `.superpowers/brainstorm/30443-1794647877/content/play-images.html` (вариант B)
- **Редактор** (макет `.superpowers/brainstorm/30443-1794647877/content/editor-images.html`, без поля описания):
  - у вопроса — блок «+ Добавить картинку» (выбрать файл / перетащить / Ctrl+V) под текстом вопроса; после загрузки — превью с «✕» (убрать) и «Заменить»
  - у варианта — значок добавления картинки; после загрузки — миниатюра; нажатие на неё — «заменить / удалить»; текст варианта становится необязательным, если есть картинка
  - пока картинка грузится — индикатор на её месте; при ошибке — короткое сообщение рядом
- **Код за основу — из NatsDoll** (разрешение пользователя): `~/Projects/NatsDoll/apps/api/src/features/admin/application/uploadProductImage.ts` (sharp: `rotate`, `resize(..., { fit: 'inside', withoutEnlargement: true })`, WebP, `limitInputPixels`), `apps/api/src/shared/lib/s3Client.ts` (Яндекс S3: таймауты, ретраи, `deleteFromS3`), фронт `apps/web/src/widgets/admin-panel/components/AdminImageUploader.vue`. Адаптировать под правила Nataskium (3 слоя, Zod, ФСД, i18n)

## Ограничения проекта

- Всё из `CLAUDE.md` и `docs/architecture.md` (раздел «Изображения»: Яндекс Object Storage через `@aws-sdk/client-s3`, переменные `YANDEX_S3_*`; «Загружаемые файлы: проверка типа и размера на сервере, случайные имена»)
- **Новые зависимости** (`sharp`, `@aws-sdk/client-s3`, `@smithy/node-http-handler`): перед установкой — проверка уязвимостей, даты релиза, поддержки (правило проекта); о рисках — пользователю до установки
- Тип файла определяется **по содержимому** (декодирование `sharp`), не по имени и не по `Content-Type` клиента. SVG и GIF не принимаются
- Глобальный лимит тела запроса API — 100 КБ (`MAX_BODY_SIZE_BYTES` в `app.ts`, на него есть тест) — для маршрута загрузки нужен отдельный лимит 15 МБ (+ запас на multipart), не ослабляя остальные маршруты
- Загрузка — только под Bearer (учитель); rate limit на загрузку
- Картинку к викторине можно прикрепить только «свою»: ссылка на картинку в данных викторины должна указывать на объект нашего хранилища, загруженный этим учителем (не произвольный URL). Проверка — на сервере при сохранении викторины
- Страница задания публичная: картинки должны открываться без авторизации (публичное чтение объектов или прокси) — без раскрытия, какой ответ правильный (имя файла/адрес не должны зависеть от правильности)
- CSP (к деплою): в `img-src` добавить домен хранилища
- В Docker для разработки `sharp` ставится под Linux — `node_modules` уже собираются в образе (`Dockerfile.dev`)
- Лимит длины тела запроса сохранения викторины (100 КБ) должен по-прежнему выдерживать 50 вопросов: ссылки на картинки входят в JSON — учесть их длину в расчёте (до 7 ссылок на вопрос)

## Решения Claude (после проверки «глазами разработчика»)

- **Копирования в этом шаге нет** (дублирования викторины и «Взять себе» пока нет в коде). Модель — «картинка принадлежит одному учителю». Когда появится «Взять себе» (публичная библиотека), картинки копируются **физически** на нового владельца: так удаление аккаунта автора не ломает чужие копии и не оставляет чужих данных
- **Квота:** отдельной квоты на объём нет. Объём уже ограничен структурой: ≤ 100 викторин × ≤ 50 вопросов × ≤ 7 картинок, каждая после сжатия — сотни КБ; плюс rate limit на загрузку и очистка «осиротевших» файлов. Принятый риск до тарифов: один аккаунт в худшем случае занимает единицы ГБ
- **Картинка не открылась** (удалена, хранилище недоступно): на странице задания и в предпросмотре на её месте — нейтральная заглушка «Картинка не загрузилась»; вариант остаётся выбираемым, проверка ответа не меняется
- **Когда удалять файл:** только после **успешного сохранения** викторины, где картинку заменили/убрали (в редакторе нет автосохранения — сохранение кнопкой). До сохранения старый файл остаётся, и опубликованная викторина не теряет картинку при незавершённом редактировании; новый файл, который так и не сохранили, удаляется очисткой «осиротевших»

## На усмотрение разработчика (технические детали)

- Размер, до которого уменьшается картинка (ориентир — NatsDoll: 1200×800 `inside`, WebP 85), можно отдельный размер для вариантов
- Формат хранения ссылки в данных вопроса (ключ объекта или полный URL) и миграция `questions` jsonb (старые викторины без картинок должны продолжать работать)
- Учёт загруженных картинок (таблица `quiz_images` с владельцем или иное) для проверки «своя картинка» и удаления
- Удаление файлов из хранилища: при замене/удалении картинки, удалении вопроса/викторины, удалении аккаунта; «осиротевшие» загрузки (загрузил, но не сохранил) — периодическая очистка. Soft delete викторины: файлы можно удалять отложенно, но при удалении аккаунта — обязательно
- Локальная разработка без настоящего бакета (MinIO в docker-compose или заглушка) — так, чтобы тесты не ходили в настоящий S3
- Числа rate limit для загрузки
- Проверка `sharp` на HEIC
- Визуальный дизайн — агент `ui-designer` по бренду; макеты — только схема
