# Типы игр: единый каталог, блок на главной и страница типа

Дата: 2026-11-25. Статус: одобрено пользователем 2026-11-25.
Макеты: `docs/design/game-types/` (вариант стиля B «Блоки»), отчёт дизайнера — `docs/design/game-types/REPORT.md`.

## Зачем
Типов игр (как «шаблоны» в Wordwall) будет много — возможно, до 30. Сейчас сведения о типах разбросаны и расходятся:
на сервере 3 типа (`ACTIVITY_KINDS`), на сайте 5 (`ActivityType` с «Пропусками» и «Картинками», у которых нет редакторов
— плитки при выборе ничего не делают). Учитель и гость должны видеть все игры в одном месте: что это за игра, как она
устроена и какие есть готовые задания в ней.

## Цели
- **Один источник правды о типах** — список, порядок, адрес страницы типа. Новый тип появляется во всех местах
  (главная, страница типа, выбор у учителя) от одной записи в каталоге плюс переводы и превью.
- **Превью типа** — схема игры в едином стиле B вместо иконки `ActivityTypeIcon` в выборе типа.
- **Блок «Познакомьтесь с нашими играми»** на главной сразу после «Как начать».
- **Страница типа**: шапка (маленькое превью слева, название справа), под ней пояснение, кнопка «Создать задание», ниже — примеры из библиотеки.
- **Выбор типа у учителя** — та же карточка с превью.
- Слово в интерфейсе — **«тип игры»** (не «шаблон»: «шаблон оформления» = визуальный стиль).

## Не цели
- Категории и фильтры типов — нет, плоский список (решение пользователя; введём, если понадобится).
- Отдельная страница «Все игры» и ссылка «← Все игры» — нет, назад — кнопкой браузера (решение пользователя).
- Обобщение кода типов (общий контракт типа, замена ручных `switch` по типу в `PlayPage`, `getPlayActivity`,
  `takenEditPath`; единый `/api/activities`) — отдельный шаг, ADR 0017, зарезервирован в ADR 0016. Здесь не делаем.
- Переименование хранимых значений (`truefalse` в `quizzes.type`) — нет.
- Пункт «Игры» в меню шапки — нет (не просили).
- Вёрстка tablet / desktop — только мобильная (как всё новое), остальное по запросу.

## Анти-цели (провал, даже если «работает»)
- Карточка типа ведёт в пустоту или на «скоро»: показываются только готовые типы.
- Превью типа путается с превью задания (визуальный стиль, узор платы, Нат внутри превью).
- Новый тип требует правки в нескольких несвязанных местах, чтобы появиться на главной, странице типа и в выборе.
- Публичный ответ API со списком по типу отдаёт больше, чем сейчас отдаёт список библиотеки (shareToken, ответы, автор).

## Подходы
- **А. Каталог в `packages/shared` + отображение в `entities/activity`** — выбрано (рекомендация, пользователь
  согласилась с порядком «каталог → интерфейс → код»). Ключ, порядок и slug адреса — в shared (их знают и API, и сайт);
  превью, переводы и карточка — на сайте. ФСД не нарушается.
- Б. Вертикальные модули «всё про тип в одной папке» — отложено до ADR 0017: требует нового слоя в ФСД и переезда ~30 файлов.
- В. Только документ со списком мест — отвергнуто: при 30 типах держится на дисциплине.

## Решения пользователя (2026-11-25)
- Тип игры, не шаблон. Текст шага 1 «Как начать»: «Выберите тип игры и визуальный стиль.»
- «Пропуски» и «Картинки» убрать отовсюду.
- Без категорий.
- Превью — вариант **B «Блоки»**: белые плашки на голубой подложке, акцент синий; зелёный и оранжевый — только «верно»/«неверно».
  Без визуального стиля, без Ната, без текста; `aria-hidden`, название всегда рядом текстом.
- Клик по карточке типа → страница типа: вверху превью, название, пояснение; ниже — примеры заданий этого типа.
- На странице типа есть кнопка **«Создать задание»** (подпись выбрана пользователем 2026-11-25): ссылка на редактор этого типа; гость проходит через вход (вариант «а»).
- Ссылки «← Все игры» нет.
- Примеры — **все публичные задания этого типа из всех разделов библиотеки вперемешку**.
- Пояснения из макета утверждены (тексты ниже).

## Что решено

### Каталог типов (`packages/shared`)
- `ACTIVITY_KINDS` остаётся списком ключей и задаёт порядок показа: `quiz`, `matching`, `truefalse`.
- Адрес страницы типа: `/games/<slug>`. Slug — в каталоге: `quiz` → `quiz`, `matching` → `matching`,
  `truefalse` → `true-false` (как адреса редакторов). Функция пути и обратный разбор slug → ключ — в `packages/shared/routes`
  (рядом с `libraryPages.ts`), язык добавляет сайт через `localePath`.
- Адрес редактора нового задания по типу — тоже из одного места (сейчас `NEW_ACTIVITY_PATHS` в `TeacherCreatePage`):
  нужен и выбору типа, и кнопке «Создать» на странице типа.

### Сайт: сущность `entities/activity`
- `ActivityType` = `ActivityKind` из shared (без `gaps`/`pictures`); убрать их из `activityTypes.ts`, `ActivityCard.vue`,
  `useMyActivities.ts`, `ManageActivities.vue`, переводов и `createHint`.
- Новый компонент превью типа (рабочее имя `GameTypePreview`): SVG-схема на тип из общего набора фигур (карточка,
  строка-заглушка, выделенная карточка, связь, значок, «верно», «неверно»), цвета — переменными, холст 4:3.
  Источник рисунка — макет `docs/design/game-types/` (вариант B).
- Карточка типа (рабочее имя `GameTypeCard`): превью 96px, название, короткое пояснение, стрелка в круге.
  Режим «ссылка» (главная) и «кнопка» (выбор у учителя). Состояния — как в макете (наведение, нажатие, фокус, reduced motion).
  В сущности, потому что её используют несколько виджетов, а виджеты не импортируют виджеты.
- `ActivityTypeIcon` в выборе типа заменяется превью; в «Моих заданиях» и других местах остаётся (см. «Остаётся строителю»).

### Переводы
- Названия и пояснения типов переезжают из `teacher.activityTypes.*` в общий раздел (рабочее имя `gameTypes.<key>`):
  `name`, `description` (коротко, для карточки), `about` (2–3 предложения, для страницы типа). Все 4 языка (ru/en/de/fr),
  все места, где сейчас `teacher.activityTypes`, переводятся на новые ключи.
- Тексты (ru, утверждены):
  - Викторина — «Вопрос и несколько вариантов ответа» / «Ученик видит вопрос и несколько вариантов ответа и выбирает
    правильный. К вопросу можно добавить картинку. Подходит для проверки фактов, терминов и правил.»
  - Сопоставление — «Соединить слова с их определениями» / «Слева — слова, справа — их определения. Ученик перетаскивает
    каждое слово к своему определению. Подходит для терминов, иностранных слов, дат и событий.»
  - Да/нет — «Решить, верно ли утверждение» / «Ученик читает утверждение и решает, верно оно или нет. Быстрая разминка
    в начале урока или проверка домашнего чтения.»
- Блок главной: заголовок «Познакомьтесь с нашими играми», подзаголовок «Нажмите на игру: покажем, как она устроена,
  и примеры готовых заданий.»
- `home.howToStart.stepFormat`: «Выберите тип игры и визуальный стиль.» (и en/de/fr).

### Главная
- Новый виджет блока после `HowToStart` в `HomePage.vue`: все типы из каталога карточками-ссылками на `/games/<slug>`.

### Страница типа `/games/<slug>`
- Тонкий файл в `app/pages/games/[slug].vue` + страница в `src/pages`. Неизвестный slug → настоящий HTTP 404 (решение строителя-проверяющего: slug известны заранее; страница раздела библиотеки статус 404 не ставит).
- Вверху: шапка — превью 80px слева, название (h1, 22px) справа; под шапкой на всю ширину пояснение `about`, затем кнопка «Создать задание» (решение пользователя 2026-11-25: превью маленькое, описание под шапкой).
- Кнопка: ссылка на редактор нового задания этого типа. Учитель попадает в редактор. Гостя middleware `teacher-auth` отправляет
  на вход с `?next=` и после входа возвращает в редактор; оттуда есть ссылка на регистрацию (после регистрации — кабинет).
  Кнопка одинаковая для гостя и учителя, auth не меняется (решение пользователя 2026-11-25, вариант «а»).
  Регистрация с возвратом в редактор — возможная отдельная задача в auth.
- Ниже «Примеры заданий»: публичные задания этого типа из всех разделов, новые сверху, карточки библиотеки (превью
  задания в его стиле, название, раздел и число вопросов, «С оценкой»/«Без оценки», «Взять себе»), «Показать ещё» —
  как в разделе библиотеки. Строка с типом в карточке скрыта (повторяет заголовок). Пустой список — текст, как в макете «Да/нет».
- SEO и `robots` — как у страниц библиотеки.

### API: список библиотеки по типу
- В `libraryListQuerySchema` новый необязательный параметр `type` (Zod enum по `ACTIVITY_KINDS`; иное — 400).
- `libraryRepository.list` получает фильтр `AND type = ${type}` фрагментом `Prisma.sql` (параметр, не строка).
  Условие публичности `PUBLIC_SQL` не меняется; набор полей ответа не меняется.
- Лимитер — тот же, что у списка библиотеки. `type` можно сочетать с `group` и `q`, но странице типа нужен только `type`.

### Выбор типа у учителя
- `ActivityTypePicker` показывает `GameTypeCard` в режиме кнопки для каждого типа каталога; переход в редактор — из
  общего пути редактора по типу.

### Документация
- `docs/architecture.md`: каталог типов, маршрут `/games/<slug>`, параметр `type` у списка библиотеки,
  чек-лист «как добавить новый тип игры» (каталог, переводы ×4, превью, редактор, игра, API).
- ADR не нужен: решение не меняет принятых правил (публичные данные — те же, что у списка библиотеки).

## Порядок (каждый шаг — отдельный небольшой дифф)
1. Текст «Как начать» (4 локали).
2. Убрать «Пропуски» и «Картинки».
3. Каталог: slug и пути в shared, общий путь редактора по типу, перенос переводов в `gameTypes`.
4. `GameTypePreview` + `GameTypeCard`; выбор типа у учителя на них.
5. API: параметр `type` у списка библиотеки.
6. Страница типа.
7. Блок на главной.
8. Документация.
