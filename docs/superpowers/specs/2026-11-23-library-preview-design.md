# Превью заданий в библиотеке и переключатель «списком / плиткой»

Дата: 2026-11-23. Статус: одобрено пользователем 2026-11-23.

## Зачем
Учитель листает раздел библиотеки (`/library/<раздел>`) и по одному тексту не понимает, как выглядит задание,
приходится открывать каждое. Как в Wordwall: у задания маленькая картинка первого вопроса — учитель выбирает глазами.

## Цели
- У каждого задания в списке раздела — миниатюра первого вопроса **в визуальном стиле задания** (ночь / день).
- Переключатель вида над списком: «плиткой» и «списком».

## Не цели
- Автор задания не показывается (решение пользователя 2026-11-23; ADR-0002 остаётся в силе — данных автора в публичном ответе нет).
- Лайки, счётчики, рейтинг — нет.
- Настоящие скриншоты (генерация картинок на сервере, хранение) — нет.
- Вёрстка tablet / desktop — только мобильная (как вся библиотека); остальное по запросу.
- Вёрстку поиска на `/library` (без раздела) не трогаем: миниатюры показывает только `LibraryBrowser`. API отдаёт превью во всех ответах списка.

## Решения пользователя
- Автора не показываем; превью — в стиле задания; подход А; сопоставление — только определения (все 2026-11-23).

## Анти-цели (провал, даже если «работает»)
- Правильные ответы или связь «слово — определение» видны в превью или в ответе API.
- Список заметно тормозит на телефоне (анимации, тяжёлые компоненты игры в каждой карточке).
- Превью не совпадает со стилем, который ученик увидит в игре.
- Изменился вид `IntroThemePreview` в настройках задания и в блоке «Визуальный стиль».

## Подходы (выбор пользователя — А)
- **А. `IntroThemePreview` получает слот для содержимого** — выбрано. Без слота рисует полоски, как сейчас;
  библиотека вставляет туда настоящий текст. Фон и цвета стиля — в одном месте, новый стиль сразу появляется везде.
- Б. Отдельный компонент превью для библиотеки — отвергнут: цвета стилей дублируются, превью может разойтись с игрой.
- Уменьшенные настоящие экраны игры (`QuizPlay` и др.) — отвергнуты: таймер, анимации, логика; 20+ на странице тормозят телефон.
- Скриншоты на сервере — отвергнуты: нужен браузер на сервере и хранилище картинок.

## Что решено

### API (`GET` списка библиотеки)
- К каждому заданию в ответе списка добавляется `introTheme` и поле превью с началом задания **без правильных ответов**:
  - викторина: текст первого вопроса, тексты вариантов (до 4), адрес картинки вопроса, если есть
    (картинки вариантов — на усмотрение строителя, см. ниже);
  - «да/нет»: первое утверждение (без ответа);
  - сопоставление: **только первые 3 определения**, слова не отдаются вовсе (решение пользователя 2026-11-23).
    Набор показанных слов выдал бы связь с показанными определениями — это отвергнуто в ADR-0013.
- `introTheme` вне каталога (стиль убрали) — сервер подставляет `DEFAULT_INTRO_THEME_KEY`, не 500: одно такое задание
  не должно ронять всю страницу; так же поступает `findTheme` в игре.
- Превью есть во всех ответах эндпоинта списка (раздел, поиск в разделе, поиск без раздела) — одна схема ответа.
- Тексты режет сервер до коротких лимитов (именованные константы в `limits.ts`), чтобы ответ остался лёгким.
- Список по-прежнему одним запросом к базе: из jsonb берутся только первые элементы (`questions->0` и т. п.),
  весь массив не распаковывается. Набор полей явный, как сейчас.
- Схема ответа — в `packages/shared/schemas/library.ts` (Zod), разбор строк — как сейчас, через схему; рассинхрон данных — 500.
- Адрес картинки — тем же `LibraryImageUrl`, что на карточке задания.

### Фронтенд
- `entities/intro-theme/IntroThemePreview.vue`: добавить слот по умолчанию. Без слота — прежние полоски
  (существующие места использования не меняются ни на пиксель). Палитра тона (`--preview-text`, `--preview-surface`,
  `--preview-line`) доступна содержимому слота.
- Новый компонент миниатюры задания (слайс в `entities/library` или `widgets/library-browser/components` — решает строитель
  по правилам ФСД): рисует первый вопрос внутри `IntroThemePreview` по типу задания:
  - викторина: вопрос + плашки вариантов 2×2 (картинка вопроса — если есть);
  - «да/нет»: утверждение + две плашки «Да» / «Нет»;
  - сопоставление: сверху ряд **пустых** плашек слов (без текста), ниже строки определений.
  Длинный текст обрезается многоточием. Миниатюра декоративная (`aria-hidden`): название и тип задания читаются из подписи.
- Картинки — `loading="lazy"`; не открылась — блок картинки скрывается, как на карточке задания.
- Без анимаций в миниатюре.
- Переключатель «плиткой / списком» над списком в `LibraryBrowser`: две кнопки-иконки с подписью для скринридера,
  `aria-pressed`. Выбор запоминается в `localStorage`; по умолчанию — «плиткой».
  - Плитка (телефон): миниатюра во всю ширину, под ней название, тип, число вопросов, оценка.
  - Список: миниатюра слева (~ треть ширины), текст справа.
  - Вся карточка кликабельна, как сейчас (растянутая ссылка).
- Тексты интерфейса — во все локали (ru, en, de, fr). После правки локалей перезапустить контейнер web.

## Оставлено строителю
- Точные лимиты обрезки текста и число вариантов/пар в превью (в рамках «до 4 вариантов, до 3 определений»).
- Показывать ли картинки вариантов викторины в миниатюре.
- Где живёт компонент миниатюры (с учётом правил импорта ФСД).
- Как именно доставать первые элементы jsonb в сыром SQL.
- Иконки переключателя.

## Проверка (что значит «работает»)
- В разделе библиотеки у заданий всех трёх типов видна миниатюра первого вопроса в цвете их стиля (ночь / день).
- Переключатель меняет вид, выбор сохраняется после перезагрузки.
- В ответе API списка нет правильных ответов, `answer`, слов сопоставления, данных автора, id, shareToken.
- `IntroThemePreview` в настройках задания и в блоке «Визуальный стиль» выглядит как раньше.
- Тесты API (схема ответа, отсутствие ответов) и компонентов; проверка в браузере на мобильной ширине.
