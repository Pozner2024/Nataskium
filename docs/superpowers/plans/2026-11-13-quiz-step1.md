# Викторина, шаг 1 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Учитель создаёт текстовую викторину в кабинете и делится ссылкой; ученик по ссылке проходит её, сервер проверяет ответы и возвращает процент и оценку.

**Architecture:** Расчёт балла, шкалы и Zod-схемы — в `packages/shared` (одни на api и web). На бэке две фичи по трём слоям: `quizzes` (кабинет, под Bearer) и `play` (публичная игра по `shareToken`, с rate limit). Вопросы хранятся JSON-колонкой одной таблицы `quizzes`; варианты адресуются индексами, перемешивает их клиент. Фронт: сущность `entities/quiz` (типы + запросы к API), виджеты `quiz-editor` и `quiz-play`, страницы кабинета и `/play/:token` (CSR).

**Tech Stack:** Nuxt 4, Vue 3, Pinia, @nuxtjs/i18n, Hono, Prisma 7 (PostgreSQL), Zod 4, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-13-quiz-step1-design.md` — читать вместе с планом.

## Global Constraints

- Всё из `CLAUDE.md`: ФСД и импорты только через `index.ts`; бэкенд — application / infrastructure / presentation, связывание только в `app.ts`; без `any`; именованные константы; комментарии только по делу; BEM в `<style scoped lang="scss">`; адаптация только миксинами; без `v-html`
- **Коммиты — только по просьбе пользователя.** В конце каждой задачи — не коммит, а предложение коммита пользователю (формат: англ., префикс `Feat:`/`Fix:`)
- Вопросов в викторине: 1–50. Вариантов в вопросе: 2–6. Правильных: ≥1, неправильных: ≥1. По умолчанию у нового вопроса 4 варианта, 1 правильный
- Длины (решение Claude, укладываются в `MAX_BODY_SIZE_BYTES = 100 КБ` из `app.ts` даже для 3-байтовых символов): название ≤ 100, вопрос ≤ 200, вариант ≤ 60 символов; всё `trim()`, пустое — ошибка
- `showAnswers` по умолчанию `true`; `gradingScale` по умолчанию `null` (оценка выключена), шкала заранее не выбирается
- Пороги шкал (оценка — если процент не ниже): five 85/70/50/0 → 5/4/3/2; ten 95/85/75/65/55/45/35/25/15/0 → 10…1; letter 90/80/70/60/0 → A/B/C/D/F
- Процент ученику — `Math.floor` от точного; оценка — по точному
- Ученик: ничего не сохраняется, имя не спрашивается, в логах — без содержимого ответов
- Язык игры — по браузеру ученика (`navigator.languages`), неподдерживаемый → `en`
- Тексты интерфейса — через `t()` во всех четырёх файлах `apps/web/src/shared/i18n/locales/{ru,en,de,fr}.ts` (`locales.test.ts` проверяет совпадение ключей)
- Только мобильная вёрстка; визуальную часть делает агент `ui-designer` по `docs/brand-colors.md`; макеты-схемы в `.superpowers/brainstorm/*/content/{editor-layout,settings-screen,student-screens-v2}.html`

## Review Focus

1. **Учитель скрыл ответы → ни один ответ API игры не раскрывает правильность** (ни `check`, ни `finish` по вопросам). Тест в задаче 5
2. **Учитель изменил викторину, пока ученик её проходит** → ученик получает понятную ошибку «Задание изменилось, начните заново», а не неверную оценку. Версия (`version`) в задачах 5 и 9
3. **Чужая или удалённая викторина** → 404 и в кабинете, и в игре (не 403: не раскрываем, что id существует). Тесты в задачах 4 и 5
4. **Ученик прислал «лишние» или повторяющиеся индексы** (больше N отметок, дубль, индекс вне диапазона) → 400, а не завышенный балл. Тест в задаче 5
5. **Викторина на 50 вопросов с максимальными длинами** проходит лимит тела запроса. Тест в задаче 4
